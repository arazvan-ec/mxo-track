Optimizador de Rutas

Sistema de optimizacion de rutas de entrega basado en VROOM (Vehicle Routing Problem solver) y OSRM (Open Source Routing Machine) para calcular distancias reales por carretera.

Arquitectura del Sistema

Cuatro componentes principales trabajan en conjunto para distribuir envios entre vehiculos y optimizar el orden de paradas.

⚙

RouteBuilder

Orquestador principal. Recibe envios y vehiculos, coordina el mapping, llama a VROOM y construye las entidades Route/RouteStop.

RouteBuilder.php
★

VROOM (VRP Solver)

Motor de optimizacion que resuelve el Vehicle Routing Problem. Distribuye jobs entre vehiculos respetando capacidades y ventanas horarias.

http://vroom:3000
☍

OSRM (Routing)

Motor de rutas sobre red vial real (OpenStreetMap). Calcula distancias y duraciones reales entre puntos — sin linea recta ni Haversine.

http://osrm:5000
♺

PostgreSQL

Persistencia de Route, RouteStop, Shipment y Vehicle. Doctrine ORM con atributos PHP 8.4 y filtro multi-tenant.

db:5432 / mxo_track

Flujo Paso a Paso

Que sucede internamente cuando el operador solicita construir rutas optimizadas.

1

Recepcion de la solicitud

El controlador RouteOptimizationApiController recibe un POST con los IDs publicos de los envios, vehiculos y opcionalmente un origen (almacen). Carga las entidades desde la base de datos aplicando el filtro multi-tenant del customer.

POST /api/routes/build JSON 
{
  "shipment_ids": ["01JEXAMPLE1", "01JEXAMPLE2", ...],
  "vehicle_ids":  ["01JVEHICLE1"],
  "origin_id":    "01JWAREHOUSE",
  "max_stops_per_route": 30
}
2

Mapping a formato VROOM

VroomRequestMapper transforma vehiculos en "vehicles" con capacidad tridimensional [peso_g, volumen_cm3, bultos], y envios en "jobs" con ubicacion, cantidad y ventanas horarias. Las coordenadas se envian en orden [longitud, latitud] (formato VROOM/OSRM).

VroomRequestMapper.php PHP 
// Vehicle -> VROOM vehicle
[
  "id"       => 0,
  "capacity" => [2500, 20000, 30],  // 2.5kg, 0.02m3, 30 bultos
  "start"    => [-3.7038, 40.4168],    // [lng, lat] Madrid
  "end"      => [-3.7038, 40.4168]     // retorno al origen
]

// Shipment -> VROOM job
[
  "id"       => 0,
  "location" => [-3.6883, 40.4530],
  "service"  => 300,                   // 5 min por entrega
  "amount"   => [500, 3000, 2],
  "time_windows" => [[32400, 43200]]  // 09:00-12:00
]
3

Optimizacion VROOM + OSRM

VroomApiClient envia un POST a VROOM con los vehiculos y jobs. VROOM internamente consulta OSRM para obtener la matriz de distancias/tiempos reales entre todos los puntos, y resuelve el VRP (Vehicle Routing Problem) con restricciones de capacidad y ventanas horarias. Devuelve la asignacion optima de jobs a vehiculos y el orden de paradas dentro de cada ruta.

Respuesta VROOM (simplificada) JSON 
{
  "code": 0,  // exito
  "routes": [{
    "vehicle": 0,
    "steps": [
      { "type": "start" },
      { "type": "job", "id": 3 },  // shipment 3 primero
      { "type": "job", "id": 0 },  // luego shipment 0
      { "type": "job", "id": 1 },
      { "type": "end" }
    ],
    "distance": 42500,  // metros
    "duration": 10800   // segundos
  }],
  "unassigned": [{ "id": 5 }]  // no cabe en ningun vehiculo
}
4

Mapping inverso y validacion

VroomResponseMapper reconstruye las entidades de dominio: crea un Route por cada ruta VROOM, con un RouteStop de origen (secuencia 0) y los stops de entrega en el orden optimizado. RouteCapacityValidator verifica que el peso, volumen y bultos totales no excedan la capacidad del vehiculo, y calcula los porcentajes de utilizacion.

5

Persistencia y respuesta

Se persisten las entidades en PostgreSQL via Doctrine. La respuesta incluye cada ruta creada con su vehiculo asignado, distancia total (km), duracion estimada (min), numero de paradas y resultado de validacion de capacidad.

Mapping Dominio ↔ VROOM

Como se transforman las entidades de Symfony al formato que espera el solver VRP.

Entidad Symfony Propiedad VROOM Conversion
Vehicle maxWeightKg capacity[0] kg × 1000 → gramos
Vehicle maxVolumeM3 capacity[1] m³ × 1,000,000 → cm³
Vehicle maxParcels capacity[2] entero directo
Shipment totalWeightKg amount[0] kg × 1000 → gramos
Shipment totalVolumeM3 amount[1] m³ × 1,000,000 → cm³
Shipment totalParcels amount[2] entero directo
Shipment latitude, longitude location [lng, lat] (invertido)
Shipment preferredWindow* time_windows HH:MM → segundos desde medianoche
VROOM result distance Route.totalDistanceKm metros ÷ 1000 → km
VROOM result duration Route.estimatedDurationMinutes segundos ÷ 60 → minutos

Modelo de Capacidad Tridimensional

VROOM maneja 3 dimensiones de capacidad simultaneamente para cada vehiculo.

⚖

Peso

Peso total en kilogramos
kg × 1000 = gramos
▢

Volumen

Espacio en metros cubicos
m³ × 1M = cm³
📦

Bultos

Cantidad de paquetes
entero directo

Ejemplo: Validacion de capacidad

RouteCapacityValidator suma los envios de una ruta y verifica contra el vehiculo asignado.

Peso — 450 kg / 600 kg 75%
Volumen — 1.8 m³ / 2.0 m³ 90%
Bultos — 28 / 30 93%

Formato de Coordenadas

Detalle critico: VROOM y OSRM usan orden [longitud, latitud], no [lat, lng].

✓ Correcto

$location = [   $shipment->getLongitude(),   $shipment->getLatitude() ];
// [-3.7038, 40.4168] = Madrid

✗ Incorrecto

$location = [   $shipment->getLatitude(),   $shipment->getLongitude() ];
// [40.4168, -3.7038] = punto en mar
OSRM URL format HTTP 
GET http://osrm:5000/route/v1/driving/{lng1},{lat1};{lng2},{lat2};{lng3},{lat3}?overview=false

// Ejemplo real:
GET http://osrm:5000/route/v1/driving/-3.7038,40.4168;-3.6883,40.4530?overview=false

Re-optimizacion de Rutas Existentes

Cuando una ruta ya existe, se puede re-optimizar el orden de paradas sin redistribuir envios.

RouteOptimizationService

1

Medir distancia actual

Usa OSRM con todos los waypoints actuales para calcular distanceBefore (km reales por carretera).

2

Construir request VROOM (1 vehiculo)

Se crea un unico vehiculo con start/end en el origen y todos los delivery stops como jobs. Sin restricciones de capacidad (ya estan asignados).

3

VROOM re-ordena las paradas

VROOM optimiza el TSP (Travelling Salesman Problem): encuentra el orden de paradas que minimiza distancia y tiempo total.

4

Aplicar nuevo orden

Se actualizan los sequence de cada RouteStop y se recalculan totalDistanceKm y estimatedDurationMinutes. Se reporta el % de mejora.

POST /api/routes/{publicId}/optimize — Respuesta JSON 
{
  "distanceBefore": 55.3,        // km antes
  "distanceAfter":  42.5,        // km despues
  "improvement":    23.1,        // % reduccion
  "estimatedDurationMinutes": 180,
  "stops": [
    { "sequence": 0, "address": "Almacen Central, Madrid" },
    { "sequence": 1, "address": "C/ Gran Via 42" },
    { "sequence": 2, "address": "C/ Alcala 15" },
    ...
  ]
}

Archivos del Sistema

Referencia rapida de los archivos clave que componen el optimizador.

Archivo Responsabilidad
Service/RouteBuilder.php Orquestador principal — coordina mapper, VROOM y response mapper
Service/VroomApiClient.php Cliente HTTP para VROOM Express API (POST JSON, timeout 30s)
